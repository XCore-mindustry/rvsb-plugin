# Strength spawner (`StrengthSpawner.java`)

Spawns crux units on a random crux spawn tile (`RedVsBluePlugin.redSpawns`) based on how strong blue is.

- Files:
  - `rvsbUnits/spawns.hjson`: global settings and spawners, plus map exceptions.
  - `rvsbUnits/mapspawns/<map>.hjson`: one file per map.
  - `rvsbUnits/unitWeights.hjson`: unit weights.
- `spawns.example.hjson` and `mapspawn.example.hjson` show every field.
- All files are [Hjson](https://hjson.github.io/): comments, unquoted keys, no commas needed between lines. Plain `.json` still works, and `.hjson` wins if both exist.
- Inside one-line `{...}` / `[...]`, keep strings quoted (`{type: "dagger"}`). An unquoted Hjson string runs to the end of the line.
- Strength values are recomputed every `updateSeconds` (default 60). Spawn checks run every second.
- It runs only while a round is going (`playing && gameRun`). It resets on world load and stops on game over.
- Server console command: `crux-spawns` shows the current values; `crux-spawns reload` re-reads the files.

## unitWeights.hjson
```hjson
default: 1
weights: {
  sei: 2.2
  vela: 0.4
}
```
Weighted HP = HP × weight of the unit type. One table shared by every map and every spawner with `weighted: true`.

## spawns.hjson
| key | meaning |
|---|---|
| `updateSeconds` | how often strength values refresh (default 60) |
| `global.spawners` | spawners for every map… |
| `global.exceptions` | …except these maps |

## mapspawns/&lt;map&gt;.hjson
| key | meaning |
|---|---|
| `spawners` | extra spawners for this map |
| `globalMultiplier` | multiplies the strength of the *global* spawners on this map (0 = they never fire) |

The file name is matched against the map's file name without extension, e.g. `mapspawns/space_ship (rerun castle).hjson`. If nothing matches, it is matched against the map's display name. Case is ignored. The file is read on every map load, so edits apply from the next map.

### Spawner
| key | default | meaning |
|---|---|---|
| `name` | | shown in logs / `crux-spawns` |
| `metric` | `sum` | one of the four below |
| `hp` | `max` | `max` = maxHealth, `currentPlus30` = health + 30 % of maxHealth |
| `weighted` | `true` | apply `unitWeights.hjson` |
| `peak` | false | the value never goes down: it keeps the highest reading since the map started |
| `decay` | 0.75 | factor for `decaying` |
| `multiplier` | 1 | strength multiplier |
| `flex` | false | value moves linearly toward the target and would reach it in `flexSeconds` (300). It re-aims at each refresh and starts at 0 |
| `playerScaling` | 0 | s: cooldown × (1 − s)^((bluePlayers − 1) / 9). So 0.5 halves the cooldown at 10 blue players and keeps shrinking it above 10. Negative values slow spawns down |
| `minStage` / `maxStage` | – | only active in these game stages (1–12) |
| `graceSeconds` | 0 | no spawns in the first N seconds of the round |
| `playersOnly` | false | count only player-controlled blue units |
| `minUnitHp` / `maxUnitHp` | – | count only units whose maxHealth is in range (raw, unweighted) |
| `include` / `exclude` | – | unit type lists |
| `buildingBonus` | – | `{"block": value}`, adds value × number of blue buildings of that block |
| `waitForDeath` | false | cooldown starts only after everything from the last spawn is dead |
| `tiers` | | see below |

### Metrics
Here *h* is the weighted HP of each counted blue unit.

| metric | value |
|---|---|
| `sum` | Σ h |
| `average` | Σ h / count |
| `avgTopHalf` | average + max h / 2 |
| `decaying` | h₁ + h₂·d + h₃·d² + …, sorted from highest |

### Tier
The highest tier with `min ≤ value < max` (and a matching stage) fires.
- After it fires, the spawner waits that tier's `cooldown` (scaled by `playerScaling`).
- Below the lowest tier, nothing happens.

| key | meaning |
|---|---|
| `min` / `max` | value range (`max` is optional = no upper limit) |
| `cooldown` | seconds until this spawner can fire again |
| `minStage` / `maxStage` | optional stage gate for this tier |
| `options` | `[{"weight": w, "units": [...]}]`. One option is picked by weight. `"units": []` = nothing this time |
| `units` | shorthand for a single option |

### Unit entry
| key | meaning |
|---|---|
| `type` | unit name (datapatch units like `dp-regent-unit` work if loaded; unknown names are skipped with one warning) |
| `wave` | instead of `type`: spawns the map's wave N groups (like `spawnwave`: groups bound to another spawn point are skipped) |
| `count` | how many (default 1) |
| `extraPerBlueUnit` | adds ⌊random(k × blue unit count)⌋ more |
| `effects` | `["boss", {"name": "overclock", "seconds": 10}]`. Default duration is permanent (or `effectSeconds`) |
| `shield`, `health`, `flag` | set on the spawned unit |

## Approximation config
`spawns.hjson` and `mapspawns/` are generated by `maps-analysis/gen_spawn_config.py` from the map world-processor analysis (`crux-spawners.md`):
- **Every spawner is weighted** (`weighted: true`, shared `unitWeights.hjson`). Of the originals only the blueStr minibosses weighted units; xexebe, q and the molten bosses used raw HP. Unit-HP filters (`minUnitHp` / `maxUnitHp`) still use raw maxHealth.
- **xexebe** → global `xexebe-A` / `xexebe-B`.
  - Weighted sum of player-unit HP (< 30k raw each) + 20k per `dp-conquer-turret`, ×map multiplier as `globalMultiplier`; 600 s grace.
  - The original reads the players' *current* health; here it is maxHealth (`hp: max`).
  - Status effects last 999 s, as in the original (`effectSeconds: 999`).
  - The dead duplicate bracket is dropped.
  - **mount** has `globalMultiplier` 0 (its in-map copy is disabled), so it never spawns. mines runs at ×0.2.
- **q comeback** → per map `q`.
  - Average weighted maxHealth of units with ≥ 600 raw HP, minus the map's excluded type.
  - Exact outcome odds, count loops (`extraPerBlueUnit: 4`), WAVE outcomes, `@flag`/`@health`.
  - Cooldown fixed at 55 s; the original is 40 + 20/unitC + 10, sped up by velas.
- **blueStr minibosses** (fortress_rvsb, abandoned_canyon, mount) → `miniboss`.
  - Weighted sum of maxHealth of all blue units, using the shared `unitWeights.hjson` (mount's writer table). fortress's own writer used sei 1.5, cyerce 3, toxopid 1, scepter 1; canyon's had no corvus entry (1).
  - abandoned_canyon's writer keeps the running maximum, so it has `peak: true`.
  - Status effects last 999 s unless the original gives a shorter time (10 s, 5 s).
- **molten bosses** → `boss-quell` (weighted sum ≥ 60k, re-arms 300 s after death) and `boss-disrupt` (≥ 80k, 600 s), with boss + overdrive for 10 s.
- `status` lines with a bare name (`spore-slowed` instead of `@status-spore-slowed`) do nothing in game, so they are left out.
- Not included: one-time unlocks, shield alarms, sand/crate/camp events, timed events. **frozen_district** and **swamp** are exceptions with no plugin spawns: they keep their in-map balancer processors. MBRL also keeps its in-map zss7 multispawner, so the plugin only adds xexebe and q there.

The maps themselves need the matching edit: the stripped maps (all other balancer world processors removed) come from `maps-analysis/strip_balancers.py`. On 11 maps the q processor also re-placed blue blocks every cycle (launch pads, fallen_reactor's cores, abandoned_metro's lights); there it is kept with only those `setblock` lines and a 50 s wait.
